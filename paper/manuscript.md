## 국문 제목
소형 로컬 LLM에서 Hermes Agent 메모리의 반복 압축이 일으키는 정보 손실 분석과 변경·예외 인지 결정적 병합

## 영문 제목
Information Loss from Repeated Memory Compression in Hermes Agent with Small Local LLMs and a Change- and Exception-Aware Deterministic Merge

## 요 약
Hermes Agent는 2,200자 영구 메모리를 LLM이 스스로 정리하고, 긴 대화는 이전 요약에 새 대화를 덧붙여 반복 요약한다. 본 연구는 Hermes의 실제 메모리 도구와 문맥 압축기를 소형 로컬 모델(Qwen3.5 4B, 9B)로 구동하여, 정답이 알려진 합성 메모 기록(질문 475개)에서 정보 손실을 측정하였다. 9B 모델의 자기 통합은 유효 사실의 30%만 남겼고, 같은 기록을 한 번에 압축할 때 68.2%이던 정확도는 10번에 나누어 압축하면 52.2%로 떨어졌다. 이에 LLM에게는 사실 추출만 맡기고 병합과 압축은 (엔티티, 속성, 범위) 키 기반의 결정적 규칙으로 처리하는 CEM을 제안한다. CEM은 2,200자에서 정확도 64.0%로 LLM 요약(51.4%)과 Hermes 에이전트(30.3%)보다 높았고, 틀린 값 응답은 LLM 요약의 절반 이하였으며, 반복 압축에도 손실이 쌓이지 않았다.

## 1. 서 론
LLM 에이전트는 오래 사용할수록 기억을 반복해서 압축하게 된다. Hermes Agent[1]에서는 2,200자로 제한된 영구 메모리 MEMORY.md가 한도를 넘으면 LLM이 세션마다 항목을 합치거나 지우고, 긴 대화는 이전 요약에 새 대화를 덧붙여 다시 요약한다. 두 경우 모두 LLM이 자신이 작성한 요약을 다시 쓰므로, 한 번 빠지거나 왜곡된 정보는 복구되지 않는다. 특히 설정은 바뀌기도 하고(8080에서 9090으로) 특정 범위에만 예외가 있기도 해서(staging만 8081), 옛 값이 현재값처럼 남거나 예외가 기본값을 덮으면 메모리에 틀린 정보가 남는다. Hermes도 여러 사실이 든 항목을 통째로 덮어쓰는 문제 때문에 replace 동작을 없앴고, 30B 미만 모델로 메모리 도구를 쓰는 것에 대해 경고한다[1]. 그러나 소형 로컬 모델에서 반복 압축으로 어떤 정보가 얼마나 손실되는지를 실제 배포 코드로 측정한 연구는 찾을 수 없었다. 본 연구는 Hermes의 실제 코드로 손실을 유형과 압축 횟수별로 측정하고, 사실 추출만 LLM에 맡기는 결정적 병합 기법 CEM(Change- and Exception-aware Memory)을 제안하여 제거 실험으로 각 요소의 기여를 확인한다.

## 2. 관련 연구
MemGPT[2]는 LLM이 스스로 메모리를 관리하는 방식을 제안하였다. Mem0[3]에서는 추출한 사실마다 LLM이 ADD/UPDATE/DELETE 중 하나를 고르며, Zep[4]은 유효 구간을 가진 그래프로 옛 사실을 무효화한다. LongMemEval[5]은 지식 갱신을 평가 항목으로 두었다. 최근에는 갱신된 정보의 소실[6], 반복 통합에 따른 오염[7], 요약 과정의 조건 탈락[8], 반복 압축에서의 급격한 손실[9]이 보고되었고, 근거 추출과 결정적 갱신을 분리하는 방법[10,11]이 제안되었다. 이들 연구는 주로 검색형 메모리와 대형 모델을 다룬다. 본 연구는 고정 글자 예산의 메모리와 반복 문맥 압축을 소형 로컬 모델로 운용할 때의 손실을 측정하고, 같은 추출 결과를 입력으로 Mem0 방식의 LLM 병합과 결정적 병합을 직접 비교한다.

## 3. 제안 방법: CEM
그림 1은 Hermes 기본 방식과 CEM을 비교한 것이다. CEM은 사실 추출, 근거 검증, 결정적 병합, 예산 배치의 네 단계로 동작한다. 먼저 LLM이 세션 메모마다 (엔티티, 속성, 범위, 값, 이전값)을 JSON 스키마 제약 출력으로 추출하고, 원문에 그대로 나타나지 않는 값은 버린다. 다음으로 엔티티, 속성, 범위 이름을 정규화하여 (엔티티, 속성, 범위) 키마다 시간순 버전 사슬을 유지한다. 예외는 별도의 키로 저장되므로 기본값을 덮어쓰지 못한다. 마지막으로 엔티티별 사실을 "Orion: API port 9090 (was 8080; staging: 8081)" 형태의 Hermes 항목 하나로 렌더링하고, 추가 글자 비용이 작은 사실부터 넣어 글자 예산 B 안의 사실 수를 최대화한다. 버전 사슬 전체는 원장 파일로 따로 보관한다. LLM은 메모리 본문을 다시 쓰지 않고 원장을 매번 같은 규칙으로 렌더링하므로, 결과가 압축 횟수와 무관하다.

## 4. 실험 설계
### 4.1 데이터와 평가
영어 템플릿으로 엔티티 24개, 엔티티당 속성 3개로 이루어진 합성 메모 기록을 만들었다(날짜별 파일 37~49개, 원문 1.0~1.3만 자). 각 속성은 50% 확률로 값이 바뀌고, 35% 확률로 범위 예외가, 12% 확률로 기각된 제안이 생기며, 메모에 속성 이름을 쓸 때마다 30% 확률로 동의어를 쓴다. 값은 에피소드 안에서 유일하므로 오답의 출처를 자동으로 판정할 수 있다. 질문은 현재값, 불변값, 직전값, 예외값, 예외 없는 범위(정답은 기본값), 자유 메모, 모름(기록 없음)의 7가지 유형이며, 독립 에피소드 3개(시드 1~3)에서 모두 475개다. 같은 모델이 각 방법이 만든 메모리만 보고 답하도록 하였다. 정확도는 맞힌 문항의 비율, 매크로 정확도는 유형별 정확도의 평균, 오답률은 정답이 있는 질문 가운데 '모름'이 아닌 틀린 값을 답한 비율이다.

### 4.2 실험 1: 2,200자 메모리
메모리 예산은 2,200자이며 길이는 Hermes와 같은 방식으로 계산하였다. 비교 방법은 최신 노트 유지, Hermes 무통합(한도를 넘게 되는 추가는 거부), LLM 요약, 구조화 요약(CEM과 같은 출력 형식), Hermes 에이전트(실제 memory 도구와 지침 사용)와 그 JSON 강제 변형이며, 원문을 보관하는 무압축 원문과 BM25 검색을 참조 기준으로 두었다. LLM을 쓰는 방법에는 모두 같은 평가 안내문을 주었다. 제거 실험으로는 이전값 보존 제거, 범위 키 제거, 같은 추출 결과의 LLM 병합(Mem0 방식), 정답 추출(Oracle)을 평가하였다.

### 4.3 실험 2: 반복 문맥 압축
기록을 시간순으로 k개(k=1, 3, 5, 10) 구간으로 나누고, Hermes ContextCompressor의 실제 갱신 프롬프트로 이전 요약과 다음 구간을 함께 요약하는 과정을 반복하였다(요약 예산은 Hermes 기본값인 2,000토큰). 비교를 위해 매번 원문 전체를 새로 요약하는 원본 참조 재압축과, 글자 제한 없이 렌더링한 CEM 원장을 함께 평가하였다.

### 4.4 실험 환경
RTX 3060, Ollama, qwen3.5:9b와 qwen3.5:4b(온도 0)를 사용했고, Hermes 커밋 67481b6의 코드를 수정 없이 import하였다. 유의성은 McNemar 검정(Holm 보정)과 군집 부트스트랩 95% 신뢰구간으로 확인하였다.

## 5. 실험 결과
### 5.1 실험 1: 2,200자 메모리
표 1에서 9B의 CEM 정확도는 64.0%로 LLM 요약(51.4%), 구조화 요약(56.4%), Hermes 에이전트(30.3%), 최신 노트 유지(25.7%)보다 높았다. 매크로 정확도 차이는 LLM 요약 대비 +10.5%p(95% CI +2.4~+18.4), 구조화 요약 대비 +9.9%p(+1.9~+17.7)였고, McNemar 검정에서도 유의했다(Holm 보정 p=0.0002, 0.035). CEM의 오답률은 7.3%로 LLM 요약(16.9%)과 무압축 원문(17.8%)의 절반 이하였고, 직전값 정확도는 59.6%로 무압축 원문(46.8%)보다도 높았다. 원문을 보관하는 무압축 원문과 BM25(약 78%)는 상한 역할을 했다. 4B(CEM 64.0%, LLM 요약 58.7%)와 개발에 쓰지 않은 시드 2~3(9B, CEM 62.7%, LLM 요약 47.1%)에서도 CEM이 가장 높았다.

### 5.2 손실의 종류
Hermes 에이전트는 한 세션에서 최대 1,437자를 한꺼번에 지웠고, 유효 사실(그 시점의 기본값과 예외값)의 보존율은 마지막에 30%까지 떨어졌다. 반면 CEM은 71%를 유지했다(그림 2). 도구 호출의 50%가 실패했고, JSON 출력을 강제해 형식 오류를 없애도 정확도는 34.7%에 그쳐 소형 모델의 통합 정책 자체가 손실의 원인으로 보인다. 최신 노트 유지와 Hermes 계열의 오류는 대부분 누락이었던 반면, LLM 요약 계열은 버전 혼동(약 10%)과 범위 혼동(4~6%)이 많았고 CEM은 각각 4.2%, 2.1%였다.

### 5.3 제거 실험
제거 실험 결과는 표 1의 아래 네 행이다. 같은 추출 결과를 LLM이 병합하면 정확도가 27.6%로 떨어졌는데, 예산에 맞춰 자르기 전에도 LLM 병합본에는 사실의 68~85%(4B는 34~47%)만 남았고 결정적 병합은 95~98%를 보존했다. 범위 키를 빼면 범위 혼동이 2.1%에서 14.9%로 늘었고, 이전값을 빼면 직전값 정확도가 59.6%에서 1.8%로 떨어졌다. 정답 추출과의 정확도 차이는 4.0%p에 그쳤다. 남은 약점은 동의어 처리이다. 동의어가 한 번 이상 쓰인 키의 정확도는 58.9%로 그렇지 않은 키(67.1%)보다 낮았다.

### 5.4 실험 2: 반복 문맥 압축
Hermes 방식의 요약본 재압축에서 정확도는 k=1, 3, 5, 10일 때 4B가 62.1, 62.5, 54.7, 45.1%, 9B가 68.2, 69.5, 60.2, 52.2%로 k=3 이후 떨어졌다(그림 3). 반복할수록 9B에서는 예외 조건의 정확도가 74.4%에서 24.4%로, 4B에서는 현재 설정값의 정확도가 80.6%에서 41.8%로 떨어졌고, 옛 값이 요약에 남아 있어도 모델은 그 값이 직전값인지 구별하지 못했다. 원본 참조 재압축은 정확도가 k=1과 같지만 매번 원문 전체를 다시 읽어야 하므로 압축이 필요한 상황에서는 쓸 수 없다. CEM 원장은 k와 관계없이 4B 81.1%, 9B 78.7%였고, 길이는 약 3,500자로 Hermes 요약의 40% 수준이었다.

## 6. 결 론
Hermes Agent의 반복 압축을 소형 로컬 LLM으로 수행한 결과, 대량 삭제, 직전값과 예외값의 혼동, 반복에 따른 누적 손실이 나타났다. LLM을 사실 추출에만 쓰고 병합과 압축을 결정적으로 수행한 CEM은 같은 예산에서 정확도를 높이고 틀린 값 응답을 절반 이하로 줄였으며, 반복 압축에서도 성능을 유지했다. 다만 영어 합성 데이터와 두 모델로 메모리와 압축 하위 시스템만 측정했고, 추출 설정은 시드 1 결과를 보고 수정한 뒤 모든 시드를 다시 실행하였으며, 동의어 때문에 같은 속성이 다른 키로 나뉘는 문제가 남아 있다. 향후 실제 사용 로그와 한국어 메모로 확장할 계획이다.
