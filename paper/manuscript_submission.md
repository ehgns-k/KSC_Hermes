# 투고용 축약판 (2~3쪽 목표, 본문 약 4,500자 + 그림 1·표 1·그림 3·그림 4)

> 근거·세부 수치는 `manuscript.md`(전체판)와 `tables/`에 있다. 이 축약판은 KSC 2~3쪽 분량에 맞춘 문장이다.

## 국문 제목
소형 로컬 LLM에서 Hermes Agent 메모리의 반복 압축이 일으키는 정보 손실 분석과 변경·예외 인지 결정적 병합

## 영문 제목
Information Loss from Repeated Memory Compression in Hermes Agent with Small Local LLMs and a Change- and Exception-Aware Deterministic Merge

## 요 약
오픈소스 LLM 에이전트 Hermes Agent는 2,200자 영구 메모리를 LLM이 스스로 정리하고, 긴 대화는 이전 요약에 새 대화를 덧붙여 반복 요약한다. 본 연구는 Hermes의
실제 메모리 도구·문맥 압축기 코드를 소형 로컬 모델(Qwen3.5 4B·9B)로 구동하고, 정답이 알려진 합성 메모 기록(질문 475개)으로 정보 손실을 유형별로 측정하였다.
9B 모델의 자기 통합은 유효 사실의 30%만 남겼고, LLM 요약은 직전 값을 거의 잃었으며(6.4%), 같은 기록을 10번에 나누어 압축하면 정답률이 4B 62.1%→45.1%,
9B 68.2%→52.2%로 떨어졌다. LLM은 사실 추출만 하고 병합·압축은 (엔티티, 속성, 범위) 키 기반 결정적 규칙으로 하는 CEM은 2,200자에서 정답률
64.0%(요약 51.4%, Hermes 30.3%)를 보였고 틀린 값 응답은 요약의 절반 이하였으며, 사실 원장을 다시 렌더링하므로 반복 압축에도 손실이 쌓이지 않았다.

## 1. 서 론
LLM 에이전트는 오래 쓸수록 기억을 **반복해서 압축**한다. Hermes Agent[1]에서 ① MEMORY.md는 2,200자로 제한되어 한도를 넘으면 LLM이 세션마다 항목을 합치거나
지우고, ② 긴 대화는 이전 요약에 새 대화를 덧붙여 다시 요약한다. LLM이 자기 요약을 다시 고쳐 쓰므로, 한 번 빠지거나 왜곡된 정보는 복구되지 않는다. 특히 설정은
바뀌고(8080→9090) 특정 범위에만 예외가 있어(staging만 8081), 옛 값이 현재값처럼 남거나 예외가 기본값을 덮으면 **틀린 기억**이 된다. Hermes도 다중 사실 항목을
덮어쓰는 문제로 `replace` 동작을 없앴고 30B 미만 모델의 메모리 도구 사용을 경고한다[1]. 그러나 소형 로컬 모델에서 반복 압축이 무엇을 얼마나 잃는지 실제 배포
코드로 측정한 연구는 찾지 못했다. 본 연구는 (1) Hermes의 실제 코드로 손실을 유형·세션·압축 횟수별로 측정하고, (2) 추출만 LLM에 맡기는 결정적 병합 기법 CEM을
Hermes 형식 그대로 적용해 제거 실험으로 각 요소의 기여를 분리한다.

## 2. 관련 연구
MemGPT[2]는 LLM의 자기 메모리 관리를, Mem0[3]는 사실별 LLM 갱신(ADD/UPDATE/DELETE)을, Zep[4]은 유효 구간으로 옛 사실을 무효화하는 그래프를 제안했다.
LongMemEval[5]은 지식 갱신을 평가 축으로 두었고, 최근 갱신 정보 소실[6], 반복 통합에 의한 오염[7], 요약 시 조건 탈락[8], 반복 압축의 급격한 손실[11]이 보고되어
근거 추출과 결정적 갱신의 분리[9,10]가 제안되었다. 이들은 주로 검색형 메모리·대형 모델을 다루며, 본 연구는 고정 글자 예산 메모리와 반복 문맥 압축을 소형 로컬
모델로 운용할 때의 손실을 버전·범위·압축 횟수 축에서 측정하고, Mem0식 LLM 병합과 결정적 병합을 같은 추출 결과 위에서 직접 비교한다.

## 3. 제안 방법: CEM
CEM(그림 1)은 ① LLM이 세션 메모마다 (엔티티, 속성, 범위, 값, 이전값)을 JSON 스키마 제약으로 추출하고, ② 원문에 그대로 없는 값을 버리며(근거 검증), ③ 이름을
정규화해 (엔티티, 속성, 범위) 키마다 시간순 버전 사슬을 유지한다(예외는 별도 키라서 기본값을 덮지 못함). ④ 엔티티당 Hermes 항목 하나
(`Orion: API port 9090 (was 8080; staging: 8081)`)로 렌더링하고, 추가 글자 비용이 가장 작은 사실부터 넣어 예산 B 안의 보존 사실 수를 최대화한다. LLM은 메모리
본문을 다시 쓰지 않고 원장을 보관·재렌더링하므로, 결과는 압축 횟수와 무관함이 설계상 보장된다.

## 4. 실험 설계
**데이터.** 영어 템플릿으로 엔티티 24개 × 속성 3개의 합성 메모 기록(날짜별 파일 37~49개, 원문 1.0~1.3만 자)을 만들었다. 변경 50%, 범위 예외 35%, 기각 제안 12%,
속성 동의어 30%를 넣고 값은 유일하게 하여 오답의 출처를 자동 판정한다. 질문은 현재값·불변값·직전값·예외값·예외 없는 범위(정답=기본값)·교훈 메모·모름(기록 없음)
7유형, 독립 에피소드 3개(시드 1~3)에서 475개이며, 같은 모델이 메모리만 보고 답한다. 매크로 정확도는 유형별 정확도의 평균, 오답률은 답이 있는 질문 중 '모름'이 아닌
틀린 값을 답한 비율이다. **실험 1**은 2,200자(Hermes 글자 수 계산)에서 최신 노트 유지, Hermes 무통합(초과 시 거부), LLM 요약, 구조화 요약(CEM과 같은 형식),
Hermes 에이전트(실제 `memory` 도구·지침·세션별 고정 스냅샷)와 그 JSON 강제 변형을 비교하고 무압축 원문·BM25를 참조선으로 둔다. LLM 방법에는 같은 평가 안내문을 주었다.
**실험 2**는 Hermes `ContextCompressor`의 실제 갱신 프롬프트로 기록을 k=1·3·5·10 구간에 나누어 (이전 요약 + 새 구간)을 반복 요약한다(Hermes 기본 2,000토큰 예산).
**환경**: RTX 3060, Ollama, qwen3.5:9b·4b(온도 0), Hermes 커밋 67481b6의 코드를 수정 없이 import, McNemar(Holm)·군집 부트스트랩 95% CI.

## 5. 실험 결과
**실험 1 (표 1).** 9B에서 CEM의 정답률은 64.0%로 LLM 요약(51.4%), 구조화 요약(56.4%), Hermes 에이전트(30.3%), 최신 노트 유지(25.7%)보다 높았다(매크로 차이: 요약 대비
+10.5%p [95% CI +2.4, +18.4], 구조화 요약 대비 +9.9%p [+1.9, +17.7]; 질문 단위 McNemar Holm p=0.0002, 0.035). 오답률은 7.3%로 요약(16.9%)·무압축 원문(17.8%)의
절반 이하였고, 직전값은 59.6%로 원문 전체를 읽은 경우(46.8%)보다 높았다. 원문을 보관하는 무압축 원문·BM25(약 78%)는 상한 역할을 했다. 4B(64.0% 대 요약 58.7%)와 개발에
쓰지 않은 시드 2–3(9B 62.7% 대 47.1%)에서도 CEM이 가장 높았다.

**손실의 종류 (그림 3).** Hermes 에이전트는 세션 도중 최대 1,437자를 한꺼번에 지웠고 유효 사실 보존율이 끝에 30%로 떨어졌다(CEM 71%). 도구 호출의 50%가 실패했고 JSON
강제로 형식 오류를 없애도 정답률이 34.7%에 그쳐, 소형 모델의 통합 정책 자체가 원인이었다. LLM 요약 계열의 오류는 누락보다 버전 혼동(약 10%)·범위 혼동(4~6%)이
특징적이었고, CEM은 각각 4.2%, 2.1%였다.

**제거 실험.** 같은 추출 결과를 LLM이 병합하면 27.6%로 떨어졌다(자르기 전에도 사실의 68~85%만 보존, 결정적 병합은 95~98%). 범위 키를 빼면 범위 혼동이 2.1%→14.9%, 이전값을
빼면 직전값이 59.6%→1.8%로 떨어졌다. 정답 추출(Oracle)과의 차이는 4.0%p로 작았고, 동의어 키(58.9%)가 기본 키(67.1%)보다 약했다.

**실험 2 (그림 4).** Hermes 반복 압축의 정답률은 k=1·3·5·10에서 4B 62.1·62.5·54.7·45.1%, 9B 68.2·69.5·60.2·52.2%로 k=3 이후 떨어졌다. 반복할수록 9B는 예외 조건
(74.4% → 24.4%), 4B는 현재 설정값(80.6%→41.8%)이 무너졌고, 변경 이력은 옛 값이 남아 있어도 직전 값으로 구별되지 않았다. 원본 참조 재압축은 원문을 매번 다시 읽어야
하므로 압축이 필요한 상황에서는 쓸 수 없다. CEM 원장은 k와 무관하게 4B 81.1%, 9B 78.7%였고 길이는 Hermes 요약의 40%(약 3.5천 자)였다.

## 6. 결 론
Hermes Agent의 반복 압축을 소형 로컬 LLM이 수행하면 대량 삭제, 직전 값·예외의 혼동, 반복에 따른 누적 손실이 발생했다. LLM을 사실 추출에만 쓰고 병합·압축을
결정적으로 수행한 CEM은 같은 예산에서 정답률을 높이고 틀린 기억을 절반 이하로 줄였으며 반복 압축에도 성능을 유지했다. 한계로 합성 영어 데이터와 두 모델, 하위 시스템
실측, 시드 1을 보고 수정한 추출 설정(이후 전 시드 재실행), 동의어 키 분할이 있으며, 실제 사용 로그와 한국어 메모로 확장할 계획이다.
